Curriculum Inventory

The MedBiquitous Curriculum Inventory standard (ANSI/MEDBIQ CI.10.1-2013) describes a health professions curriculum for a reporting period: its events, expectations (competencies and objectives), academic levels, sequence and integrating themes. Its objective is "to provide a data structure that allows one to represent a health professions curriculum in a standard format", so that curriculum data can be exchanged and aggregated, for example in the AAMC Curriculum Inventory of North American medical schools.

Document types and versions

TypeVersionNamespace
curriculum-inventory-v11.0 (approved standard, 2013) http://ns.medbiq.org/curriculuminventory/v1/
curriculum-inventory-v10"v10", the AAMC point release for the 2022 upload seasonhttp://ns.medbiq.org/curriculuminventory/v10/

Both have the root element CurriculumInventory. The point release differs from 1.0 in three places:

  • A sequence block names its academic levels with SequenceBlockLevels (StartingAcademicLevel and EndingAcademicLevel) instead of a single Level, so that a block can span several levels (a longitudinal course).
  • The Description of the report is optional.
  • An instructional method can give the time spent on it (instructionalMethodDuration, such as PT1H30M).

Version 2.0 of the standard is a working draft and is not supported.

Structure of a report

ElementContent
ReportReportID, Institution (the InstitutionInfoType of the Healthcare Professional Profile), Program, Title, ReportDate, the reporting period (ReportingStartDate, ReportingEndDate), Language, Description and SupportingLink.
EventsThe education and assessment events (lectures, labs, clinical experiences, examinations…), each with an id, a title, a duration, keywords, competency object references, resource types and at least one instructional or assessment method.
ExpectationsCompetency objects (competencies, learning objectives, learning outcomes; MedBiquitous Competency Object) and competency frameworks that organize them. A competency object is identified by its Healthcare LOM identifier (lom:lom/lom:general/lom:identifier/lom:entry).
AcademicLevelsLevelsInProgram and one Level per level (years, phases), numbered 1 to 10.
SequenceSequence blocks (years, phases, courses, clerkships). A block has timing (dates, a duration or both), academic levels, and either events (SequenceBlockEvent) or nested blocks (SequenceBlockReference), or both. Attributes model parallel blocks, electives, selectives and tracks.
IntegrationIntegration blocks: themes that run through the curriculum, with the competency objects, events and sequence blocks that belong to them.

Parts of a report refer to each other with XPath expressions, all in one line:

  • /CurriculumInventory/Events/Event[@id='E1'] (events),
  • /CurriculumInventory/Sequence/SequenceBlock[@id='Y1'] (sequence blocks),
  • /CurriculumInventory/AcademicLevels/Level[@number='1'] (academic levels),
  • /CurriculumInventory/Expectations/CompetencyObject[lom:lom/lom:general/lom:identifier/lom:entry='X'] (competency objects).

Editor pages

Besides the overview, tree and XML pages, a Curriculum Inventory document has these form pages (the same for both versions; the sequence block fields follow the version):

PageWhat it edits
ReportTitle, report ID and domain, report date, reporting period, language, description, supporting link.
Institution and ProgramInstitution name, ID and address; program name, ID, educational context, profession and specialty (with vocabulary source and source ID).
EventsThe list of events. For the selected event: id, title, duration, description, keywords, interprofessional, competency object references, and the instructional methods, assessment methods and resource types, offered from the standardized vocabulary while typing; their attributes (primary, purpose, source, source ID, v10 duration) are edited in the detail lists below them.
ExpectationsCompetency objects (Healthcare LOM identifier, title and description, status, categories, references) and competency frameworks (included objects and relations).
Academic LevelsLevelsInProgram and the levels (number, label, description).
SequenceThe sequence description and the sequence blocks: attributes (required, order, minimum, maximum, track), timing, academic levels (Level in 1.0, starting and ending level in v10), clerkship model, competency object references, pre- and postconditions, events and nested blocks.
IntegrationThe integration description and the integration blocks with their references.

Rules

Besides the XML Schemas, Hermes checks these rules of the specification (and of the Implementation Guidelines) that the schemas don't express:

SeverityRule
ErrorEvery EventReference, SequenceBlockReference, CompetencyObjectReference and academic level reference (Level, StartingAcademicLevel, EndingAcademicLevel) resolves to an event, sequence block, competency object or level of the report.
ErrorEvent, sequence block and integration block ids are unique within the report; competency object identifiers are unique.
ErrorLevelsInProgram equals the number of Level elements.
ErrorAn event with instructional methods marks one as primary.
ErrorIn a sequence block whose order is Ordered, every SequenceBlockReference has an order.
ErrorDates are in order: ReportingStartDate ≤ ReportingEndDate, and the start and end dates of sequence blocks and their events; in v10 the starting academic level is not after the ending level.
ErrorA sequence block's minimum is not greater than its maximum or than the number of its nested blocks; Timing holds at most one Duration and one Dates; a sequence block does not contain itself through nested blocks.
WarningEvery event is part of a sequence block (and the report has a Sequence); an event is listed once per block.
WarningSequence block and event dates lie within the reporting period and within the dates of the enclosing block; in v10 a nested block's levels lie within its parent's.
WarningLevel numbers are unique and sequential from 1; the report date is not before the reporting period.
WarningOnly one instructional method of an event is primary; in v10 the instructional method durations of an event don't exceed its EventDuration.
WarningRequired In Track is used inside a track (a block with track="true"); maximum does not exceed the number of nested blocks; ordered positions are not repeated.
WarningA sourceID of the standardized vocabulary (IM…, AM…, RE…) matches its term and the kind of element; competency objects have an identifier; the institution has a name.
InfoRecommended practice: terms from the Curriculum Inventory Standardized Instructional and Assessment Methods and Resource Types, with their codes in source and sourceID; a domain on ReportID, ProgramID and InstitutionID; titles of competency objects; competency frameworks include competency objects of the report; competency objects are referenced; a block with only a duration is nested in a block with dates.

Templates and samples

A new Curriculum Inventory document (New Document…, see Creating Documents) starts from a template: one event, one competency object, one academic level and one sequence block that references them, valid against the schemas and the rules. Replace them with your own and add more.

Two fictional samples come with Hermes (in samples/curriculum-inventory of the standards bundle):

  • bayou-state-md-2024-2025-v10.xml (v10): a four-year M.D. curriculum with organ-system courses, a longitudinal course over two levels, clerkship rotations, electives, a capstone, a competency framework and two integration themes.
  • pelican-bay-md-2015-2016-v1.xml (1.0): a curriculum with a clerkship year that has a main and a rural track, and a block of selectives.
