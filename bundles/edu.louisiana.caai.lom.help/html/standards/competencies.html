Competencies: Competency Framework, Competency Object and Performance Framework

Three MedBiquitous standards describe what learners are expected to be able to do and how well: a Competency Object states one expectation (a competency, learning outcome, learning objective or professional role), a Competency Framework organizes competency objects and their relationships, and a Performance Framework describes levels of performance (such as milestones) for the competencies of a framework. All three describe themselves with embedded Healthcare LOM metadata.

The editor recognizes the documents by root element and namespace. The title of a document is the title of its Healthcare LOM metadata (lom/general/title); its description is the LOM description or a summary (such as “8 included competencies, 3 relations”).

Structure of the documents

Competency Object

A competency object is “an umbrella term used to describe any abstract statement of learning or performance expectations, and information related to the statement.” It contains:

  • lom:lom — the identifier (required, a URI with the catalog URI), the title (required: the statement itself), the description (recommended), publisher and copyright.
  • Status — Active (default) or Retired; Replaces and IsReplacedBy — URIs of earlier and later versions.
  • Category — categories modeled after the Atom category element: a required term, an optional scheme URI and a display label.
  • References/Reference — references to the literature; SupportingInformation — a Link or formatted XHTML text.

Competency Framework

A competency framework is “an organized and structured representation of a set of interrelated and purposeful competency objects.” It contains:

  • lom:lom — identifier (a URI), title, description, version, status, publisher, educational context, rights and target profession.
  • EffectiveDate, RetiredDate, Replaces, IsReplacedBy — versioning (“whenever a substantive change has been made to a competency framework, a new unique identifier and version number should be assigned”).
  • SupportingInformation — links to or embeds the human readable framework and its introduction.
  • Includes (one or more) — the Catalog and Entry of every competency of the framework: “All competencies included in the framework must be referenced using the Includes element, including any competency object or framework referenced in a relations element.”
  • Relation — Reference1 has a broader (skos:broader), narrower (skos:narrower) or related (skos:related) concept Reference2. Broader and narrower are converse; “Cyclical references are forbidden as are any references that result in a hierarchical conflict.”

Performance Framework

A performance framework describes “one or more sets of performance levels to be used in assessing competence or performance.” It contains:

  • lom:lom, the dates and versions and SupportingInformation (an RDF Reference or XHTML text), as in a competency framework.
  • PerformanceScale (one or more) — an id and the scores of the LeastCompetent and MostCompetent ends; lower numbers may mean higher competence.
  • Component (one or more) — an id, titles, abbreviations, Competency references (two RDF references: “once to reference a competency object, once to reference the relevant competency framework”), authors, reviewers, Thresholds (a minimum acceptable score for a decision such as entrustment), AdditionalInformation, and either ComponentReferences to nested components or a PerformanceLevelSet.
  • PerformanceLevelSet — the PerformanceScaleReference and two or more PerformanceLevels, each with a DisplayOrder, a Score (a single value or a Range), labels, Indicators (behavioral markers with an id) and additional information.

Rules Hermes checks

Besides the XML Schemas, Hermes checks these rules of the specifications (and of the meaning of the data). They appear in the Validation view as Rules problems.

RuleTypesSeverity
The LOM title is present (“Defines the title … Required”).allerror
An identifier with the catalog URI is present and its entry is an absolute URI (“identifiers must be in the form of a URI”).allerror
A description, a publisher (role publisher) and a life-cycle status are recommended.all (publisher and status: frameworks)info
The effective date is not after the retired date.frameworkserror
A retired framework names its replacement (IsReplacedBy); a replaced framework gives its retired date. frameworkswarning (retired) / info (retiring, replaced)
Replaces and IsReplacedBy are absolute URIs, not the document's own identifier and not the same URI in both.allwarning / error
Supporting information links are absolute URIs (“Link must contain a valid URI”).framework, objectwarning
A competency is included only once; included competencies with the catalog URI have URI entries. frameworkwarning / error
Both references of each relation are included competencies.frameworkerror
No relation relates a competency to itself, and broader/narrower relations form no cycle. frameworkerror
A relation is not stated twice (a broader b equals b narrower a).frameworkwarning
The Status is stated; a Retired object names its replacement; an Active object is not replaced. objectwarning
Category terms are not empty, schemes are URIs, categories are not repeated.object error / warning
A performance scale has two different ends; unused scales are reported.performance error / info
ComponentReference names another component (not itself, not a scale or indicator), without cycles. performanceerror
PerformanceScaleReference names a performance scale.performanceerror
Display orders are unique within a level set; scores lie on the scale.performance error
Scores follow the display order consistently (rising or falling), levels don't share or overlap scores, ranges run from the least to the most competent end.performancewarning
Threshold scores lie on the component's scale.performancewarning

Additional information positions are unique per label; labels are the recommended values (assessment method, background, example, note, reference, resource).performancewarning / info

Hermes cannot check that the referenced competency objects and frameworks exist: they are other documents, usually on the web.

Samples and templates

New documents start from a template with the title, the language, a urn:uuid: identifier and the date filled in: a framework with two included competencies and one relation, a competency object with its status and a category, and a performance framework with a 1–5 scale and one component with two levels.

The samples (folder samples/competencies of the plug-in edu.louisiana.caai.medbiq.model) are fictional, except the sample of the MedBiquitous implementation toolkit:

  • core-competencies-framework.xml — six core competency domains (modeled on the ACGME domains) with patient care sub-competencies and relations.
  • competency-patient-care.xml, competency-professionalism.xml, competency-pc1-history.xml — competency objects of that framework.
  • milestones-performance-framework.xml — milestones-like levels, nested components, thresholds, indicators and score ranges.
  • sample_framework.xml — “The Competent Physician”, the sample of the MedBiquitous Competency Framework toolkit (© 2012 MedBiquitous Consortium).
