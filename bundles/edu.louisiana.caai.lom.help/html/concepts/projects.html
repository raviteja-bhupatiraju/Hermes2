Projects and the Workspace

A project is a folder of MedBiquitous documents (Healthcare LOM records and documents of the other standards, which can be mixed) that you manage together. Projects are validated in the background, searched, and listed in the Projects and Problems views.

What a project is

  • A project is an ordinary folder anywhere on your disk with a small project file, hermes-project.json, that holds the project's name, description and the format of new documents (see The Project File).
  • Every MedBiquitous document below the folder belongs to the project, including files you add with the file explorer, another editor or a version-control tool. Hidden folders (names starting with a dot) and the build-output folders target, bin and node_modules are skipped.
  • A file counts as a document if it has the extension .xml, .lom or .json and is a document of a supported standard, recognized by its root element and namespace: for example a Healthcare LOM record (an XML file whose root element is lom in the IEEE LOM namespace, or a JSON file whose top-level object has a "lom" object member) or a Curriculum Inventory (root element CurriculumInventory). See Documents: XML and JSON for all root elements. Only Healthcare LOM has a JSON form.
  • Subfolders are allowed and shown in the Projects view.

The workspace

Hermes 2 keeps its open projects in an Eclipse workspace in ~/.hermes2/workspace (in your home folder), together with the preferences and the window layout. Each project is a workspace project with the Hermes project nature whose content stays in the project folder; the workspace writes an Eclipse .project file next to hermes-project.json. Because the name, description and format are kept in the project file, a project folder can be opened again later, or by another installation of Hermes 2, without the workspace.

The workspace is refreshed automatically when files change outside the application.

Background validation

The project's builder (MedBiquitous Validation) validates a document whenever it is created or changed, also outside the application, and after each save, whatever its standard. It checks the same things as the Validation view (XML Schema, model constraints and the rules of the document's standard) and reports every problem as a marker in the Problems view, where double-clicking opens the document at the field concerned. The Projects view shows each document's state with an icon (error, warning, or the XML/JSON icon when it is valid) and, in the tooltip of a project, the number of documents and how many have errors or warnings.

Projects versus single files

You can also open any MedBiquitous document directly with File > Open…. A document outside a project is validated in its editor (Validation view and inline markers) but does not appear in the Problems view and is not included in project searches.

Closing and deleting

  • Close Project removes a project from the Projects view and the workspace; the files stay on the disk. Use Open Project… to show it again.
  • Delete on documents or folders deletes the files from the disk after confirmation.

Projects that earlier versions of Hermes 2 kept in the preferences are moved into the workspace on the first start.
