Healthcare LOM in Brief

Healthcare Learning Object Metadata (HLOM) v1, ANSI/MEDBIQ LO.10.1-2008, is the MedBiquitous profile of IEEE Learning Object Metadata (LOM, IEEE 1484.12.1, XML binding IEEE 1484.12.3). It describes healthcare learning resources: continuing-education courses and live activities, and medical images, video and other assets.

Healthcare LOM is one of the MedBiquitous standards that Hermes 2 edits, and the one with the most complete support (JSON form, quick fixes, terminologies, completeness, CSV import and HTML reports). Other standards embed HLOM descriptions: Curriculum Inventory, Competency Object and Activity Report documents, for example, can describe a resource with a lom element, which their form pages show as an embedded description.

Structure of a record

An HLOM record is an XML document whose root element is lom in the IEEE LOM namespace http://ltsc.ieee.org/xsd/LOM. It contains the nine LOM categories and one healthcare extension:

CategoryDescribesEditor page
1 GeneralIdentifier, title, language, description, keywords, coverage, structure, aggregation levelGeneral
2 Life CycleVersion, status and contributors (authors, publishers, reviewers…) with dates Life Cycle
3 Meta-MetadataThe record itself: its identifiers, contributors, metadata schemas and languageMeta-Metadata
4 TechnicalFormats (MIME types), size, locations (URLs), requirements, duration Technical
5 EducationalInteractivity, learning resource types, intended end user roles, contexts, difficulty, typical learning timeEducational
6 RightsCost, copyright and other restrictions, conditions of useRights
7 RelationRelated resources and the kind of relationshipRelation
8 AnnotationComments on the educational use, with author and dateAnnotation
9 ClassificationClassifications by purpose (for example competency) with taxon paths from a taxonomyClassification
healthcareMetadataThe MedBiquitous extensions: healthcareEducation (credits, target audience, disclosures, schedule, activity location) and healthcareAsset (clinical history, image type, specimen, magnification, dimensions)Healthcare Education, Healthcare Asset

The healthcare extension elements use the namespace http://ns.medbiq.org/lom/extend/v1/ (prefix hx); the activity location address uses http://ns.medbiq.org/address/v1/ (prefix a).

What makes a record conformant

A conformant HLOM instance validates against the HLOM XML Schemas, is a conforming IEEE LOM XML instance, and meets the specification's Additional Requirements:

  • metaMetadata declares the metadata schemas LOMv1.0 and HEALTHCARE_LOMv1 (and SCORM_CAM_v1.3 if applicable);
  • healthcareMetadata occurs once.

Hermes 2 checks both requirements and can add what is missing; see Validation. All healthcare extension elements are optional.

Recurring patterns

Multilingual text (LanguageString)
Titles, descriptions, keywords and similar elements hold one or more string entries, each with a language attribute such as en-US. Hermes 2 warns about text without language.
Vocabularies
Elements such as role, learning resource type, context and classification purpose take a source and a value. The source is LOMv1.0 for IEEE LOM terms and HEALTHCARE_LOMv1 for the MedBiquitous healthcare terms. The editor writes the matching source when you pick a term.
Coded keywords
A keyword may carry hx:source (a terminology such as MeSH, SNOMED or UMLS) and hx:id (the code in that terminology, for example the MeSH descriptor D009203).
Credits
One credits entry per type of credit (for example one for CME and one for CNE), each with accrediting body, credit type, unit, number of credits, pacing and providers.
People and organizations
Contributors are stored as vCards (vCard 3.0 text).
Dates and durations
Dates follow XML Schema (2026-03-01, 2026-05-14T08:30:00); durations use ISO 8601 (PT1H30M).

For the complete element reference, the healthcare vocabularies, credit acronyms, professions and specialties, open the HLOM Guide (Help > HLOM Guide). The specification itself is available as Help > Specification (PDF).
