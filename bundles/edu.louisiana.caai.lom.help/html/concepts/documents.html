Documents: XML and JSON

Documents of all MedBiquitous standards are XML documents defined by the standards' XML Schemas. Healthcare LOM records can in addition be stored in a JSON form that follows the naming of the MedBiquitous Healthcare LOM JSON Schema; both forms hold exactly the same information and are edited and validated the same way.

How the standard of a document is recognized

Hermes 2 recognizes a document by its root element and namespace, whatever its file name or extension (the usual extensions are .xml, .lom and, for HLOM, .json):

StandardRoot element
Healthcare LOM 1.0lom in http://ltsc.ieee.org/xsd/LOM (or, in the JSON form, a top-level "lom" object)
Curriculum Inventory 1.0 and v10CurriculumInventory
Competency Framework 1.0, Competency Object 1.0, Performance Framework 1.0 CompetencyFramework, CompetencyObject, PerformanceFramework
Activity Report 1.0 and 2.0ActivityReports
Medical Education Metrics 1.0, MEMS Survey Items 1.0MedicalEducationMetrics, SurveyItems
Healthcare Professional Profile 1.0Members
Virtual Patient Data, Activity Model and Data Availability Model 1.0 VirtualPatientData, ActivityModel, DataAvailabilityModel

The root elements of the other standards are in their namespaces below http://ns.medbiq.org/; the namespace also tells the versions apart (for example Activity Report …/activityreport/v1/ and …/v2/). See The MedBiquitous Standards. Files of other kinds are not opened as MedBiquitous documents.

Which form a file uses

This applies to Healthcare LOM records; documents of the other standards are always XML.

  • Files with the extension .json are stored in the JSON form.
  • All other files (normally .xml, also .lom) are stored as XML.

New documents use the format chosen in the new-document wizard; its default comes from the project (New documents in the project properties) or from the preference Create new documents in the JSON form (.json) instead of XML.

One model, several views of it

When a document is opened, it is read into a model generated from the XML Schemas of its standard (for HLOM, the HLOM XML Schemas; HLOM elements embedded in documents of other standards use the same HLOM model). The form pages, the Document Tree, the XML page and, for HLOM, the JSON page all show this one model:

  • Edits on the form pages and in the tree change the model directly and are undoable.
  • Text edits on the XML or JSON page are applied to the model when you leave the page or save. If the text cannot be applied, you are asked to fix it or discard your text changes.
  • Saving writes the model in the file's form. Element order is restored from the schema, so a JSON document saved as XML is valid against the XML Schema.

Elements and attributes that the schemas don't define (custom extensions) are kept and shown on the Document Tree page.

Converting between XML and JSON

Only Healthcare LOM records have a JSON form; documents of the other standards can't be converted to JSON.

  • Save As: choose File > Save As… and enter a name ending in .json or .xml. The document is written in that form.
  • Projects view: right-click documents and choose Convert to JSON or Convert to XML. The converted file is written next to the original (with a numbered name if the name is taken) and the original file is removed. Documents that can't be read without errors must be opened and repaired first.

The conversion is lossless for HLOM content. XML comments and processing instructions are not carried into the JSON form.

Broken files

A file that can't be read completely (for example XML that is not well-formed) still opens: its original text is shown on the XML or JSON page, with the load problems in the Validation view, so you can repair it in place. A document can't be saved while the XML or JSON page holds text with errors.

The JSON Schema (Healthcare LOM)

JSON documents carry a "$schema" member that references the MedBiquitous Healthcare LOM JSON Schema. The published JSON Schema set is incomplete (most referenced component schemas are not published and several references don't resolve), so Hermes 2 references it but doesn't validate against it. JSON documents are instead validated exactly like XML documents: XML Schema, model constraints and HLOM rules, with load problems reported at JSON line numbers.
