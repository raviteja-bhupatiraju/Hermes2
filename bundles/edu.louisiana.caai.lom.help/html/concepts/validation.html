Validation

Hermes 2 checks every document against the published XML Schemas of its MedBiquitous standard, the constraints of its data model and the rules of the standard. Validation works offline: the schemas of all supported standards (with the schemas they import) and the terminologies are bundled with the application.

The three checks

Each problem names the check that reported it (the Check column of the Validation view):

CheckWhat it verifies
XML SchemaThe XML form of the document against the bundled XML Schemas of its standard: element names and order, required content, enumerations and data types. For Healthcare LOM these are the HLOM v1 XML Schemas (IEEE LOM binding, healthcare extensions, address schema); JSON documents are checked through their XML form. For the other standards, the schemas published at http://ns.medbiq.org/ for the document's namespace and version.
ModelConstraints of the model generated from the schemas: data types, patterns and multiplicities. A document without the root element of its standard (for HLOM, <lom>) is reported here.
RulesFor Healthcare LOM: the specification's Additional Requirements (metadata schemas, healthcareMetadata) and consistency checks the schemas can't express: title and description, languages of text, credits, dates, disclosures, MeSH descriptor IDs and terminology codes. See Validation Rules and Quick Fixes. For the other standards, the rules of that standard that the schemas can't express (for example the reporting period and the references between the parts of a Curriculum Inventory) are reported under the same check; they are described in the topics of the standards.

Severities

  • Error: the document is not a conformant instance of its standard (for example, not a conformant Healthcare LOM instance).
  • Warning: probably a mistake, for example credits marked as available but not described.
  • Info: a best practice, for example a missing description. Infos can be hidden with the preference Show informational hints (best practices).

When documents are validated

  • While you edit: the active document is validated in the background after each change (by default 600 milliseconds after the last change; see Setting Preferences).
  • On demand: the Validate button of the main tool bar and Validate Now in the Validation view.
  • In projects: every project document is validated in the background whenever it changes, also outside the application.
  • Outside Hermes 2: with the hermes validate command and, in other editors, with the Hermes language server (see below).

One check everywhere

The editor, the background validation of projects (Problems view), the hermes command line tool and the language server all run the same check, for documents of every standard. A document therefore has the same problems wherever it is checked, and each problem is reported at its line and column in the file as written (for HLOM JSON documents, at the JSON line).

  • Command line: hermes validate <file|folder>… checks documents and reports their problems as text, JSON or SARIF (--format); --fail-on error|warning|never sets when the exit code is 1, for use in scripts and continuous integration. hermes info shows the type of each document (standard and version), its title and its problem counts, and hermes search finds text in the field values of documents of any standard. The tool is in the cli folder of the installation (or the separate hermes-cli archive).
  • Language server: hermes lsp validates MedBiquitous documents while they are edited in any editor with Language Server Protocol support and leaves other XML and JSON files alone.

The commands that change documents, hermes convert (to JSON) and hermes fix (automatic quick fixes), apply to Healthcare LOM records, the only documents with a JSON form and quick fixes.

Quick fixes (Healthcare LOM)

Many problems of Healthcare LOM records can be repaired automatically; documents of the other standards have no quick fixes, so their problems are corrected on the form pages, in the tree or on the XML page. A light bulb marks problems with a quick fix; press Ctrl+1 in the Validation view or on the XML page to choose one. Problems that need your input offer “Go to” fixes that show the right field. Fix All applies every automatic fix in one undoable step. See Validating and Fixing Problems.
