Editor Pages

The editor shows the pages of the document's standard. For a Healthcare LOM record it has twelve form pages, the Document Tree and the XML and JSON source pages; this reference lists the sections and fields of each of them. For the meaning and permitted values of each HLOM element, follow the links to the HLOM Guide or press Shift+F1 in a field. Documents of the other MedBiquitous standards have the pages described in Pages of the other standards.

Overview

Summary, completeness and validation status of the record. The page is read-only; its links open the page where something can be added.

SectionContents
Summary cardThe kind of record (for example “Educational offering · CME 1.5 Credit · Learner paced” or “Medical image asset”), title, description, languages and the keywords, with MeSH-coded keywords highlighted. Add a title appears when the title is missing.
Key factsVersion & status, Contributors, Published, Resource type, Context, Format; for educational offerings also Expires, Target audience, Credits and Location; for assets Image. Facts that are Not specified link to their page.
CompletenessA score of the recommended Healthcare LOM elements (based on the HLOM specification) rated Excellent (90 or more), Good (70 or more), Fair (45 or more) or Needs work, with a progress bar per category and the missing elements in its tooltip. Categories that don't apply to the record are marked Not applicable.
ValidationThe number of errors, warnings and infos and the first problems (click one to go to it), or “Conforms to the Healthcare LOM v1 schemas and rules”. Show problems opens the Validation view.
Next stepsThe most valuable additions to this record, each linking to its page.

Document Tree

All elements of the document, including custom extension elements. Select an element to edit it in the Properties view; the context menu (and the Document menu) add children and siblings. The Outline view shows the same tree.

XML

The XML source with syntax highlighting, content assist, live schema checking, quick fixes, formatting, comment toggling, matching-tag highlighting and folding. See Editing XML and JSON.

JSON

The document in the JSON form of the MedBiquitous Healthcare LOM JSON Schema, with highlighting, content assist, live syntax checking and formatting. See The JSON Format. Healthcare LOM only.

Pages of the other standards

Documents of Curriculum Inventory, Competency Framework, Competency Object, Performance Framework, Activity Report, Medical Education Metrics, MEMS Survey Items, Healthcare Professional Profile and the Virtual Patient standards have these pages:

PageContents
OverviewThe standard and version, the title and description of the document and a link to the standard on medbiq.org; Contents: the parts of the root element with their counts (or “The document has no content yet.”); Validation: the numbers of errors, warnings and infos and the first problems (click one to go to it). Read-only.
Form pagesDefined per standard and grouped in the navigation sidebar. The fields are rendered from the standard's schemas: text, drop-downs for enumerations, date pickers, lists and master/detail blocks for repeated elements, embedded Healthcare LOM descriptions, and hints for formatted text (XHTML) that is edited on the XML page. See Form pages of the other standards and the topic of each standard under The MedBiquitous Standards.
Document TreeAll elements of the document, as for Healthcare LOM.
XMLThe XML source with content assist and hovers from the standard's schemas and live schema checking. No quick fixes.

There is no JSON page, and the Healthcare LOM tools (MeSH and terminology lookups, quick fixes, completeness) are not available for these documents.
