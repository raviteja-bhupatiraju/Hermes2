The Project File

Every project folder contains a project file, hermes-project.json, with the project's name, description and the format of new documents. A folder with this file is a project.

Example

{
  "name": "CME Catalog 2026",
  "description": "Continuing education courses of the department",
  "format": "xml",
  "created": "2026-10-13"
}

Members

MemberTypeDescriptionIf missing or empty
namestringThe project's name, shown in the Projects view.The name of the project folder
descriptionstringAn optional description, shown in the project's tooltip.Empty
formatstringThe format of new Healthcare LOM documents: "xml" or "json" (case is ignored). Documents of the other standards are always XML."xml"
createdstringThe creation date (ISO 8601, YYYY-MM-DD), written when the project is created with Hermes 2.Unknown (not written)

Other members are ignored, and they are not kept when Hermes 2 writes the file. The file is UTF-8 encoded JSON; if it isn't valid JSON, the project can't be opened and the error names the file.

When the file is written

  • When you create a project (New Project).
  • When you open a folder that is not a project yet and confirm Make it a project?.
  • When you change the project's Properties.

The file is not a MedBiquitous document and is never listed among the project's documents. The Eclipse workspace additionally writes a .project file into the folder for its own bookkeeping.

Which files belong to a project

Every document of a supported MedBiquitous standard (.xml, .lom or .json, recognized by its root element and namespace) below the project folder, except in hidden folders and in target, bin and node_modules. See Projects and the Workspace.

Because the project file is plain JSON and the documents are ordinary files, project folders can be kept in version control and opened by other installations of Hermes 2.
