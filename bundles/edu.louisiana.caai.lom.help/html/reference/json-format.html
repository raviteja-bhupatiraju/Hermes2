The JSON Format

Healthcare LOM records with the extension .json are stored in a JSON form that follows the naming of the MedBiquitous Healthcare LOM JSON Schema (the other MedBiquitous standards have no JSON form and are always stored as XML). This page describes the mapping between the XML and the JSON form, for developers and for anyone who edits the JSON page.

Document

A JSON document is an object with these members:

MemberContents
"$schema"The MedBiquitous JSON Schema: https://ns.medbiq.org/jsonSchema/healthcare-learning-object-metadata/healthcarelom.schema.json. It is referenced but not used for validation (the published schema set is incomplete).
"$schemaLocation"Only if the XML form had a non-default xsi:schemaLocation; kept for the XML form.
"$namespaces"Only if needed: prefixes of namespaces other than the known ones, mapped to their URIs.
"lom"The record: the lom element.

Mapping rules

  • Every element becomes a member named after the element: "general", "title", "healthcareEducation", "creditType", ….
  • Elements that may repeat according to the model are arrays. Because the IEEE LOM binding defines most LOM elements as repeatable choices, most LOM members (including "general", "title", "string", "source" and "value") are written as arrays.
  • An element with only text is a string, or a number or boolean when its schema type is numeric or boolean (for example "numberOfCredits": 1.5).
  • An element whose type has text content and attributes is an object with the attributes and "content" for the text. Multilingual text therefore reads {"language": "en", "content": "…"}, and vocabulary sources and values read {"content": "LOMv1.0"}.
  • An element with child elements is an object. Attributes declared by the schema are members with the attribute name (for example a keyword's "source" and "id"); other attributes are prefixed with @.
  • Elements and attributes the HLOM schemas don't define are kept with a prefix: name. The prefixes hx (healthcare extensions), a (address) and xsi are known; other prefixes are declared in "$namespaces".
  • Comments and processing instructions are not kept.

Example

An excerpt of the JSON form of a CME course (the sample “Insulin Pump Therapy”), as written by Hermes 2:

{
  "$schema": "https://ns.medbiq.org/jsonSchema/healthcare-learning-object-metadata/healthcarelom.schema.json",
  "lom": {
    "general": [
      {
        "title": [
          { "string": [ { "language": "en", "content": "Insulin Pump Therapy" } ] }
        ],
        "keyword": [
          {
            "id": "D007332",
            "source": "MeSH",
            "string": [ { "language": "en", "content": "insulin infusion systems" } ]
          }
        ]
      }
    ],
    "lifeCycle": [
      {
        "contribute": [
          {
            "role": [
              { "source": [ { "content": "LOMv1.0" } ], "value": [ { "content": "author" } ] }
            ],
            "entity": [ { "content": "BEGIN:VCARD\nFN:John Doe\nEND:VCARD" } ]
          }
        ]
      }
    ],
    "healthcareMetadata": [
      {
        "healthcareEducation": {
          "creditsAvailable": "yes",
          "credits": [
            {
              "accreditingBody": "ACCME",
              "creditType": "CME",
              "creditUnit": "Credit",
              "pacing": "learner paced",
              "numberOfCredits": 1.5
            }
          ],
          "participationModality": [ "technology based" ]
        }
      }
    ]
  }
}

Reading JSON

When reading, Hermes 2 is lenient: a single object or value may be given where an array is expected, and an element with only text may be written as a plain string. So hand-written JSON can use the compact forms "title": {"string": {"language": "en", "content": "…"}} and "role": {"source": "LOMv1.0", "value": "author"}. Members may be in any order; the XML Schema's element order is restored when the document is converted to XML. Saving writes the full form shown above.

Syntax errors and invalid values are reported at their JSON line. The document is then validated like an XML document (XML Schema, model constraints and HLOM rules).

The content assist of the JSON page (Ctrl+Space) proposes the members allowed at the caret with a value skeleton, so you rarely need to type the structure by hand.
