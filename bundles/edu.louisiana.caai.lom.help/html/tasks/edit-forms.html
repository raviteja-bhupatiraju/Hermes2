Editing with the Form Pages

The form pages present a document as labeled fields: for a Healthcare LOM record, each LOM category and the healthcare extensions; for the other MedBiquitous standards, the pages defined for that standard (see Form pages of the other standards). Every edit is applied to the document immediately and can be undone.

Moving around

  • Click a page in the navigation sidebar on the left of the editor. Badges show how many problems each page has.
  • On the Overview page, links such as Not specified in Key facts and the items under Next steps open the right page.
  • Double-click a problem in the Validation or Problems view to go straight to its field.

The fields of each page are listed in Editor Pages.

Getting help on a field

  • Hover over a field or its label to read the specification's description of the element.
  • Press F1 to show the field's context help in the Help view, or, in a Healthcare LOM record, Shift+F1 to open its topic in the HLOM Guide.

Kinds of fields (Healthcare LOM)

Text fields
Type the value. Some fields offer suggestions from the specification while you type, for example accrediting bodies, activity certifications, professions, specialties, reading levels, MIME types and terminology names.
Multilingual text
Fields such as Title and Description have a language box next to the text (a language tag such as en-US). The translations button opens the Translations dialog, where each row holds the same text in another language: use Add and Remove and click a cell to edit it. The button's tooltip tells you when more languages are available.
Lists of text entries
Keywords, descriptions, coverage, professions and similar lists: type a value and press Enter (or click Add). The list's tool bar removes, moves up and down, and edits translations of the selected entry. Keyword lists also have Look Up… for coded keywords; see Keywords and Terminologies.
Value lists (tokens)
Languages, formats, locations, metadata schemas, entities and similar values are shown as tokens followed by an input field. Type or pick a value and press Enter. A token's close button removes it, double-clicking edits it, and its context menu moves it.
Vocabulary fields
A drop-down or a group of check boxes with the IEEE LOM terms and the MedBiquitous healthcare terms in separate groups. The editor writes the matching source (LOMv1.0 or HEALTHCARE_LOMv1) with the value.
Healthcare enumerations
Fields such as Credit type, Pacing, Off-label use or Medical image type offer the values defined by the healthcare schema. Credit type and Credit unit tooltips explain the acronyms.
Dates
Date fields have a date picker. Dates are stored as XML Schema dates (2026-03-01) or date-times (2026-05-14T08:30:00).
Durations
Typical learning time and Duration take ISO 8601 durations such as PT45M or PT1H30M.
Master/detail blocks
Repeated structures (identifiers, contributors, educational uses, credits, classifications, relations, annotations, requirements) are listed on the left with their details on the right. Use the block's tool bar to Add (+), Remove, and move entries up or down; select an entry to edit its details.

Form pages of the other standards

Documents of the other MedBiquitous standards open on an Overview page: the standard and version, the title and description, a link to the standard on medbiq.org, the Contents of the document (the parts of the root element with their counts) and the Validation results. The form pages that follow are defined for each standard, grouped in the navigation sidebar like the Healthcare LOM pages; for example, a Curriculum Inventory has Report, Institution and Program, Events, Expectations, Academic Levels, Sequence and Integration. The pages of each standard are described in its topic.

The forms are rendered from the standard's schemas:

Text and numbers
Single-line or multi-line text fields, checked against the data type of the schema (numbers, identifiers…); some fields suggest values recommended by the standard while you type.
Enumerations
A drop-down with the values the schema allows.
Dates
A date picker; dates are stored as XML Schema dates or date-times.
Lists and master/detail blocks
Repeated elements (events, expectations, competencies, reports, members…) are listed on the left with their details on the right; the block's tool bar adds, removes and moves entries.
Embedded Healthcare LOM descriptions
Where a standard describes a resource with a Healthcare LOM lom element (for example in a Curriculum Inventory, a Competency Object or an Activity Report), the form shows the fields of the description and identification of that HLOM description.
Formatted text (XHTML)
Elements with rich XHTML content are shown as a hint (“formatted text (XHTML), edited on the XML page”); edit them on the XML page.

Deeply nested content that the forms don't show is edited in the Document Tree. Validation markers, problem badges, undo, and field help on hover work as on the Healthcare LOM pages. The Healthcare LOM tools (MeSH and terminology lookups, vocabulary fields, vCards, translations, quick fixes, completeness) are not available for the other standards.

People and organizations (vCards, Healthcare LOM)

Contributors and annotation authors are stored as vCards.

  1. On the Life Cycle or Meta-Metadata page, select a contributor and click Add vCard… (on the Annotation page: Compose vCard…).
  2. In the Contributor vCard dialog, enter the Full name, Organization and Email.
  3. Click OK. A vCard 3.0 entry is generated and added.

Undo, clearing and saving

  • All pages and views share one undo history: Edit > Undo (Ctrl+Z) and Redo (Ctrl+Y).
  • Clearing a field removes the element, and containers that became empty are removed too, so no empty elements are left behind.
  • Opening or viewing a page never changes the document; only edits make it dirty.
  • Save with Ctrl+S.

Validation markers

Fields with problems are marked inline, and the navigation sidebar shows the number of problems per page. Hover over a marker to read the message. See Validating and Fixing Problems.
