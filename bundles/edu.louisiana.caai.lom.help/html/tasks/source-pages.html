Editing XML and JSON

Every document has an XML page in the Source group of the navigation sidebar; Healthcare LOM records also have a JSON page. Both show the whole document as text and can be edited directly. Documents of the other MedBiquitous standards have no JSON page.

How text edits are applied

  • Text changes are applied to the document when you leave the page or save. Until then the other pages show the previous state.
  • If the text has errors when you leave the page, you are asked to fix it or to discard your text changes.
  • A document can't be saved while the XML or JSON page holds text with errors.
  • Undo and redo on the XML page work on the text; on the other pages they work on the model.

The XML page

FeatureHow to use it
Content assistCtrl+Space: the child elements allowed at the caret (inserted with their end tag), the end tag of the current element, enumeration values and attribute names, taken from the schemas of the document's standard. In Healthcare LOM records also: skeletons for vocabularies and multilingual text, vocabulary terms in <value> (updating the sibling <source>), sources, healthcare enumeration values, language tags and values recommended by the specification.
HoversHover over an element or attribute name to read its help, taken for the other standards from the schemas of the document's standard.
Live checkingThe text is checked against the XML Schema of the document's standard as you type: squiggles in the text, markers in the vertical and overview rulers, and hovers with the messages. The document's validation results are shown as well.
Quick fixHealthcare LOM: Ctrl+1 on a line with a problem offers the same fixes as the Validation view. If you have changed the text since the last validation, apply your edits (and validate again) first.
FormatCtrl+Shift+F or Format in the context menu re-indents the XML.
Toggle commentCtrl+/ comments or uncomments the selected lines.
Navigation aidsMatching start and end tags are highlighted; elements can be folded.
Find/ReplaceCtrl+F.

In documents of the other standards, the XML page is also where formatted text (XHTML content, for example in competency statements or virtual patient data) is edited; the form pages only point to it.

The JSON page (Healthcare LOM)

The JSON page shows a Healthcare LOM record in the JSON form described in The JSON Format.

FeatureHow to use it
Content assistCtrl+Space: member names allowed in the current object that are not yet present (inserted with a value skeleton), and values: vocabulary terms and sources, healthcare enumeration values, language tags, recommended values, keyword sources and terminology codes. Assist also works in incomplete JSON.
Live syntax checkingSyntax errors are marked as you type. Problems found when the JSON is applied are reported at JSON line numbers.

The Document Tree page

The Document Tree page shows every element of the document, including custom extension elements that the form pages don't show. Select an element to see and edit its attributes in the Properties view; use New Child and New Sibling in the context menu or the Document menu to add elements.

Repairing a broken file

A file that isn't well-formed opens with its original text on the XML (or JSON) page and the load problems in the Validation view. Correct the text; when it can be read, leave the page or save, and the form pages show the repaired document.
