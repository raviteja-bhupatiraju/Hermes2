Validating and Fixing Problems

Documents of every MedBiquitous standard are validated as you edit. This topic shows how to review the problems, jump to the fields concerned and repair them, in Healthcare LOM records also with quick fixes, and how to validate documents outside Hermes 2.

Review the problems of the active document

  1. Open the Validation view (bottom of the window), or click Validate on the main tool bar, which shows the view and validates the active document.
  2. Read the list. The view's description summarizes the result (for example “The document is valid.”, or the number of problems and how many have quick fixes). Columns:
    • a light bulb when a quick fix is available;
    • Description: the message;
    • Element: the element path;
    • Line: the line in the file, where known;
    • Check: XML Schema, Model or Rules (for documents of the other standards, the rules of their standard).
  3. Double-click a problem (or choose Go to Element in the context menu) to show the field concerned.

Apply a quick fix (Healthcare LOM)

Quick fixes and Fix All are available for Healthcare LOM records. Problems of documents of the other standards are corrected on the form pages, in the Document Tree or on the XML page; double-clicking the problem shows the place.

  1. Select a problem marked with a light bulb.
  2. Press Ctrl+1 (or choose Quick Fix… in the context menu). The Quick Fix popup lists the fixes with a description of the selected one.
  3. Press Enter or double-click to apply a fix; Esc closes the popup. The context menu's Quick Fix submenu offers the same fixes directly.

Fixes that change the document are listed first. Problems that only you can resolve, such as a missing off-label description, offer “Go to” fixes that show the right field. Every fix is undoable with Ctrl+Z.

On the XML page, Ctrl+1 offers the fixes of the problems on the caret's line.

Fix all automatic problems at once (Healthcare LOM)

  1. Click Fix All on the Validation view's tool bar (or in its context menu). The tooltip tells how many problems can be repaired.
  2. The Fix All dialog lists each automatic fix with the problem it repairs. Deselect the fixes you don't want (Select All and Deselect All help).
  3. Click Apply n Fixes.

The selected fixes are applied as a single change; Edit > Undo (Ctrl+Z) reverts all of them. Problems that need your input are not listed; use their “Go to” quick fixes.

The automatic fixes are: declaring the metadata schemas LOMv1.0 and HEALTHCARE_LOMv1, adding healthcareMetadata, setting a missing text language to the document language, and swapping inverted activity or credit dates. Fixes for inconsistent credit information (mark credits as available or not, add a credit entry, remove the credit information) are offered individually because you must choose between them. The complete list is in Validation Rules and Quick Fixes.

Problems across a project

The Problems view lists the problems of all documents of your projects, of every standard (marker type MedBiquitous Problem), at their positions in the files, and is kept up to date in the background, also when files change outside Hermes 2. Double-click a problem to open the document at the field concerned. The Projects view marks documents with errors and warnings.

Other places that show problems

  • The Overview page's Validation card shows the counts of errors, warnings and infos and the first problems; Show problems opens the Validation view.
  • The navigation sidebar shows a badge with the number of problems on each page.
  • Form fields with problems are marked inline.

Validate outside Hermes 2

The hermes command line tool (in the cli folder of the installation, or the separate hermes-cli archive for any system with Java) and the language server run the same check as the editor and the Problems view, for documents of every standard, and report each problem at its line and column in the file as written.

CommandPurpose
hermes validate <file|folder>…Checks documents (XML Schema, model constraints and the standard's rules). --format text|json|sarif, --output, --min-severity; --fail-on error|warning|never sets when the exit code is 1. SARIF output can be uploaded to code scanning services.
hermes info <file>…Summarizes documents: the type (standard and version), the title, and the numbers of errors, warnings and infos; for Healthcare LOM records also the kind, languages, keywords, contributors, credits and audience.
hermes search <text> <file|folder>…Finds text in the field values of documents of any standard (--in takes the field groups of every standard).
hermes format <file>…Rewrites documents in the canonical layout (--check only reports).
hermes convert, hermes fixHealthcare LOM: convert between XML and JSON, apply the automatic quick fixes.
hermes lspThe language server: validates MedBiquitous documents while they are edited in any editor with Language Server Protocol support.

Validation settings

In Window > Preferences… > Healthcare LOM > Validation you can turn off validation after each change, change its delay, and hide informational hints. See Setting Preferences.

To practice the repair workflow, the Hermes 2 source repository contains a deliberately broken record, samples/invalid/opioid-stewardship-draft.xml.
